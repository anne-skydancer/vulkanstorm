# Shader families, interface ABI and migration contracts

Baseline `1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5`, 2026-10-03. This supplements [resources/platform](resources-platform.md) R05 and the main pass audit. The source inventory contains **225 GLSL files in 11 families**, with **690 C++ registration/variant records** in [shader-registration.csv](shader-registration.csv). Registration rows are not distinct linked programs. Shader-library files may have no `main`, be attached to several programs/stages or be replaced through class fallback. The source interface/branch census covers all 225 files; the contracts below trace family producer/consumer interfaces and significant current variant routes. It does **not** prove every arithmetic path or macro permutation behaves identically on every device. H01–H11 give one design record per inventoried family, including dormant error shaders.

## Shader assembly and actual ABI

The registration roots are [LLViewerShaderMgr::loadBasicShaders](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/newview/llviewershadermgr.cpp#L765), water L 925, effects L 1018, deferred L 1096, object L 3079, avatar L 3171 and interface L 3234. `setShaders` L 532 selects class/capability/settings routes. [LLShaderMgr::attachShaderFeatures](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llshadermgr.cpp#L68) links library objects in an explicit dependency order: atmosphere/light helpers, skinning, texture lookup, global/deferred/G-buffer, SSR/shadow/probe/AO, gamma/atmosphere/water fog, terrain and tonemap. The suffix `F` does not guarantee fragment-only use: `environment/srgbF` is also attached to vertex programs.

[loadShaderFile](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llshadermgr.cpp#L462) searches from selected class downward to class1; injects GL/GLSL-version header, stage defines, global/local permutations, G-buffer flags/type, vendor workaround and indexed texture lookup. The `[EXTRA_CODE_HERE]` marker controls injected-code placement. It compiles shader objects; [LLGLSLShader::createShader](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llglslshader.cpp#L407) attaches features, links/maps and may retry a lower shader level. Therefore compiling each `.glsl` independently is insufficient qualification. Reproduce linked dependency closure, then compile Vulkan modules with explicit include/module organization.

The **vertex ABI** is [reserved attribute order](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llshadermgr.cpp#L1222) plus `mapAttributes` (`llglslshader.cpp` L 651) and [setupVertexBuffer](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llvertexbuffer.cpp#L1727). Positions are float 3 in a 16-byte stride; texture index is an unsigned integer read from the fourth position component's bits. Diffuse/emissive colors are four normalized U8 channels. Joint IDs are four U16 integer channels; weights/tangents/normals and UVs have distinct stride/format requirements. Binding may deliberately substitute emissive storage for diffuse-color attribute. Preserve these semantics in explicit Vulkan binding/location/format descriptions; do not reinterpret normalized colors as integers or numeric-cast the texture-index bits.

The **uniform ABI** combines reserved enums/names, active GL reflection and dynamic hash-named setters. [mapUniforms](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llglslshader.cpp#L850) constructs active sampler channels and special-cases diffuse ordering. It is not a predefined Vulkan descriptor layout. GL uses separate binding namespaces: the PPLL image, SSBO and atomic counter all use binding 0; native Vulkan requires distinct descriptor bindings or explicitly compatible resource declarations. Matrix/light hashes and alpha variant flags trigger CPU uniform uploads; notably `make_gltf_variant` changes lighting feature flags **after compilation** to drive `LLRender::syncMatrices`. Extract those CPU data dependencies rather than blindly copying compile flags.

The [GL program cache](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/llrender/llshadermgr.cpp#L1022) checks cache version and stores shader-hash keyed binaries. L 1139 attempts `glProgramBinary`, checks error/link status, removes invalid data and falls back to compilation. A Vulkan shader module cache and device-specific pipeline cache need separate keys/compatibility policy; existing `.shaderbin` data cannot be reused.

## Cross-family encodings and branch classification

Current indexed texture channels are hardcoded to four at baseline llviewershadermgr.cpp 573–579; RenderMaxTextureIndex is not the active batch count. The paired framework design compares actual sampler/array/binding pressure, not that setting alone.

- **G-buffer ABI:** `pbropaqueF` converts base/emissive samples from sRGB in shader, writes linear color and packed linear occlusion/roughness/metal, encodes normal plus environment and G-buffer flag; HUD branch converts final output back to sRGB because HUD occurs after gamma. Some comments label emissive output sRGB despite explicit conversion; record operations and consumer formats, not comment alone. [globalF](https://github.com/anne-skydancer/vulkanstorm/blob/1a490c3cb7ed60124169bf4bf6ad61a6ae1eeec5/indra/newview/app_settings/shaders/class1/deferred/globalF.glsl#L46) packs spherical normal XY; injected flags are floating values 0/.34/.67/1 with tolerance .1 (`llshadermgr.cpp` L 636). `HAS_EMISSIVE` changes attachment use. Avoid double sRGB conversion by switching formats without changing math.
- **Coordinates:** deferred utility L 325 reconstructs GL NDC Z as `2*depth-1`; PPLL uses window depth near 0/far 1 and descending sort, integer `gl_FragCoord.xy` texel fetch. Many `*Rect` uniforms are actually normalized sampler 2D. Vulkan view/projection ABI must resolve clip Z/Y, front-face and viewport origin consistently; update reconstruction and every depth comparison together. Keep pixel coordinates distinct from normalized UV, including SMAA flip macros, snapshot borders, depth copies and auxiliary views.
- **Shadows:** `loadBasicShaders` L 829 injects `SUN_SHADOW` for detail>=1 and `SPOT_SHADOW` for >=2; per-program `HAS_SUN_SHADOW` is separately based on deferred level/settings. `shadowUtil` comparison samplers, six matrices and depth biases are not interchangeable flags. Pipeline creation keys distinguish shader-feature policy from attachment raster depth/bias state.
- **Active/conditional PPLL:** fragment injection is Windows/Linux GL>=4.4; alpha CPU routes set only mode 0/1 (`lldrawpoolalpha.cpp` L 230/L 233). `fullbrightF` includes mode 2/3/4 depth-peel code under `ALPHA_DEPTH_PEEL`, with no current shader-manager define or CPU invocations found. Classify this as **dormant**, not a supported peeling feature. PPLL nodes pack half RG/BA, float-depth bits and predecessor; resolve has 32-layer/256-traversal bounds with opaque-depth rejection. Preserve bounded overflow/compositing behavior first; future algorithm changes require separate design decision.
- **Registered/debug is not mandatory device capability:** geometry normal visualization is conditional ordinary debug facility; a native tier can replace that mechanism while preserving the optional display. Library fallback class2/3 may contain empty or reduced functions; an existing file does not prove high-quality route active on a given machine.

## Language/toolchain recommendation and Khronos basis

DiligentCore is the leading mature GHI candidate, bgfx the comparator. Delegate shader/resource binding and PSO infrastructure where the qualified library expresses the ABI; keep viewer semantic schema/reflection checks. Do not build a new RHI under a shader adapter. Extensive unexpressible ABI/state requirements reject the candidate rather than imply bespoke capacity.

Shader toolchains and imported helper implementations require provenance, license/build and actual-capability checks. Vendor-origin utilities are eligible; retain/use qualified CAS/FSR or other helpers when they improve the supported outcome, with independent functional alternatives for unsupported devices. Compare common solutions at fair quality and input resolution rather than selecting on vendor ID. Optional NVIDIA-only NVRHI must lower the same shader semantic ABI without making its binding/tooling mandatory for the independently controlled common AMD/Intel GHI path. All variants need reflection and parity tests. The deeper pinned comparison now verifies actual optional Diligent DLSS Vulkan and FSR1 providers; it also shows FSR outputs alpha 1, DLSS temporal inputs/build limits and bgfx shader/interop constraints. See [framework-comparison.md](framework-comparison.md).

Prefer **Vulkan GLSL→SPIR-V for the first parity tier**: the current code already has a large GLSL/math library, making explicit blocks/locations, dependency reorganization and coordinate corrections a narrower semantic change than a simultaneous language rewrite. This is an engineering inference, not a Khronos rule. HLSL/DXC remains a technical alternative subject to provenance/license/build and selected-dependency review while preserving independently controlled default architecture; no toolchain is approved here. Use a representative family bake-off (PBR skinning, water, PPLL, UI, SMAA) to measure eligible toolchain/debug/reflection friction. Do not select a GHI solely to avoid GLSL conversion, or assume a language conversion preserves layout/precision.

Khronos references below were browsed 2026-10-03 (`latest` documentation; pin an SDK/spec revision when implementing). The [HLSL in Vulkan guide](https://docs.vulkan.org/guide/latest/hlsl.html) explains that both languages produce SPIR-V, supports explicit Vulkan bindings and recommends DXC for HLSL. This supports keeping both language options open, not a performance claim. [Shader Memory Layout](https://docs.vulkan.org/guide/latest/shader_memory_layout.html) explains std140/std430/scalar layout distinctions: preserve/reflection-check GLTF/node/palette packing before adopting alternative layout features. The [Shader Interfaces specification](https://docs.vulkan.org/spec/latest/chapters/interfaces.html) supplies normative interface-matching/location/block requirements; emitted SPIR-V and pipeline inputs must agree. [Depth guide](https://docs.vulkan.org/guide/latest/depth.html) explains Vulkan clip/depth conventions and available controls; it underpins the coordinated projection/reconstruction conversion above. These are requirement/explanation references; proposed module layout and first-tier language choice are viewer-specific designs.

Pipeline/shader generation owns modules, descriptor layout and pipeline layout together. Reflection signatures include vertex format/location, block offsets/ranges, sampler/image type, stage access and attachment outputs. Compile-time defines that change ABI produce separate signatures. Small value-only variants can be specialization constants; unsupported optional variants get explicit fallback. Graph declares shader storage-write→resolve storage-read and attachment-write→sampled-read dependencies using R04/R06 rules, preserving across-view histories and retired shader/resource generations.

## Qualification gaps that remain visible

1. The file/registration census and 11 family contracts do not enumerate every possible linked-program/configuration combination. Generate realized variant manifest from source settings/capabilities before implementation; compile/reflection-validate that manifest and record eliminated impossible variants.
2. Dynamic named uniform setters, sampler ordering and matrix/light feature side effects require a complete CPU producer→reflected block field reconciliation. Missing fields must fail validation, not become default zero.
3. G-buffer attachment format versus explicit conversion versus consumer math requires numerical captures; comments alone cannot settle color encoding. Test classic/PBR/HUD/emissive-buffer on/off and probe/mirror/capture outputs.
4. No per-pixel arithmetic equivalence or all-vendor precision proof was performed. Capture controlled animated/avatar/PBR/water/transparency/UI cases, including negative/NaN/HDR extremes and bounded OIT overflow, with unchanged reference tolerances.
5. AA portable-library macro branches (CAS/SMAA/FXAA), dormant historical branches and runtime class fallbacks need realized-route validation. Not every macro found in imported library code is a supported current viewer option.
6. External GHI selection must demonstrate reflected custom shader ABI, unsigned storage-image atomics/SSBO access, exact attachments and readback, and caller-visible resource completion. A generic triangle/UI demo does not qualify these requirements.

This audit writes design documents only. No shader, viewer settings, pipeline behavior or test baseline was modified.
