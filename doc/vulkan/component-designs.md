# Compatible component designs and traceability

These are proposed designs for the GL contracts in [source-audit.md](source-audit.md). They use the interfaces in [architecture.md](architecture.md), implemented through a qualified mature GHI. DiligentCore leads qualification and bgfx is the comparator; bespoke backend machinery is infeasible under current capacity. Delegate backend infrastructure rather than recreate it behind these semantic interfaces. The exact paired API mapping and unresolved constraints for every listed record are in [framework-contract-matrix.csv](framework-contract-matrix.csv), with complete adapter designs in [framework-comparison.md](framework-comparison.md). No backend is integrated. CPU-only work remains CPU work. All formats/usages are queried before enabling a feature; no measured performance or runtime parity is claimed.

The default functional renderer remains independently controlled. Vendor-origin supporting utilities are eligible when actual capabilities, licensing/build compatibility and measured outcomes qualify, with equivalent independent functional fallback. This includes potential NVIDIA/AMD helpers and standard Vulkan allocation utilities. Optional NVIDIA-only NVRHI remains a separate adapter exception requiring all component contracts equally and a complete independent AMD/Intel path; NVIDIA also retains the common GHI path. Existing shader helpers are evaluated for quality/parity and dependency scope, not rejected for origin. No helper or backend is automatically selected or implemented.

Common **C-DRAW**: versioned geometry inputs + material/view/skin blocks → PSO indexed/vertex draw. Upload TRANSFER_WRITE precedes vertex/index/shader read; material sampled images are shader-read layout; render attachment writes precede later samples. PSO explicitly owns topology, cull/front-face/depth/bias, independent RGB/A blend and masks. Missing geometry/material/palette produces documented fallback or skipped draw, never accesses stale memory. Frame snapshot pins every generation through completion; handles alone do not prove readiness. K1/K2/K3/K6.

Common **C-POST**: sampled immutable source/depth/history plus constants → distinct color output. Dynamic-rendering fullscreen triangle initially preserves existing sampling/math; color-output writes precede fragment-sample reads; ping/pong logical resources do not overlap while sampled. Graph may alias physical storage after final consumer only. Compute postprocessing is an alternative requiring dispatch/bandwidth/parity evidence, not presumed faster. K1/K2/K3.

Common **C-VIEW**: snapshot + ViewContext → per-view target generation and output tickets. Culling remains CPU initially, with explicit camera/render mask; view owns extent/history/clip/environment and never mutates camera globals during worker recording. Resize/cancel preserves old valid generation until GPU completion. K1/K4/K7/K9.

## Coordinate and encoding ABI (applies to every component)

Initial parity keeps standard depth near 0/far 1 and existing LESS/LEQUAL tests, not reverse-Z. CPU scene/camera space stays unchanged. At the vertex ABI convert GL clip z to Vulkan `0.5*z+0.5*w` **once**, or build the equivalent view projection in CPU; inverse projections, depth reconstruction and shadow transforms use the paired convention. Prefer one documented screen origin/top-left canonical render image convention. The GHI adapter normalizes exactly one viewport/projection Y policy; an external adapter may already use negative-height viewports. Account for that explicitly rather than applying a second accidental Y flip. Front-face/culling derives from resulting winding; negative viewport and mirrors must each be accounted for. Shader gl_FragCoord indexing and PPLL pixel heads refer to the same physical pixel as detached depth.

Texture assets preserve their own orientation; render-image UV transforms are explicit metadata by producer. Cube face directions/layers and reflected clip signs are independent of image row order. UI bottom-left rectangles/scissors convert to canonical screen coordinates once; CPU picking rays use the same camera/viewport conventions; snapshot readback reconstructs existing requested bottom-up/top-down and tiled output conventions, respecting row pitch. GPU depth sampling never applies a display gamma transform.

Use exact per-stage color encoding from the audit: mixed legacy/PBR G-buffer remains explicit shader-managed encoding, screen HDR RGB and glow A, manually encoded HUD/post output. Present initially to UNORM SDR surface with existing gamma output; choose sRGB surface only with matched final shader removal of manual encoding, preventing double gamma. Hardware HDR presentation is outside initial parity scope. K3/K4/K8 support valid interfaces/formats; the compatibility choice is viewer-specific and must be tested with gradients, transparency, winding, mirrors, text and tiled captures.
